AgentGuard5

One VM, one sandbox per test.

  • Web app, API, queue and Postgres in Docker Compose on one VM
  • Serverless Inference plans each scan
  • Every test runs in a fresh Playwright container, deleted afterwards

Status. Runs locally today; the Vultr deployment is in progress. Approvals are recorded only: nothing is sent to GitHub or by email yet.

AgentGuard6

Designed for Vultr.

Cloud Compute VM

Hosts the app, API, database, queue and every sandbox. Owning Docker and the host firewall is what lets us cut each sandbox off at the network level.

Serverless Inference

Test planning and summaries over an OpenAI-compatible API. No GPUs to manage.

Firewall

Only 80/443, plus SSH from the team, can reach the VM.

Deployment in progress. The stack runs locally today. The inference client is tested with a scripted model, not yet against the live Vultr endpoint; if the model fails, the built-in fallback plan runs.

AgentGuard7

Containment first. We assume the site is hostile.

The containment demo task tries to reach the cloud metadata address. UI shown with demo data.

  • One container per task, always destroyed
  • CPU, memory, process and time limits; non-root
  • No Docker socket, no host files, no secrets inside
  • Private IPs, localhost and cloud metadata blocked in 3 layers
  • Credentials never reach the LLM; secrets are redacted
  • Tamper-evident, hash-chained audit log
